# NextPlay Sportswear: My Account compact layout and cloud QR investigation

## Source
Based on `Archive(20261019-143546).zip` supplied October 19, 2026. Changes are presentation-only in `resources/css/storefront.css`. There are **no database, route, controller, or permission changes**.

## Compact account UI
The shared My Account CSS now controls the consistent sizing of the sidebar, page header, headings, buttons, fields, cards, and spacing. The rules apply to the existing account frame and all of its non-artwork content: Dashboard, Profile & Security, Order Center, Order History, Rewards, Refer a Friend, Returns & Exchanges, Order Downloads, Saved Addresses, Payment Methods, plus order actions and details using the account frame. The preexisting artwork-proof page layouts retain their own styles, although the sidebar is shared.

Implementation goals:
- Preserve the Expose font variables and centralized theme/CTA colors.
- No new JS, Blade templates, or dependencies.
- Keep all account links and form validation untouched.
- Maintain 40px+ mobile navigation targets, focus styles, and responsive stacking.
- Match Tailwind utility classes with `[class~="..."]` attributes to avoid CSS `@apply` circular-dependency errors.

## Apply
1. Back up `resources/css/storefront.css`.
2. Copy the patch into the Laravel project root.
3. Build the production assets:

```bash
npm run build
php artisan view:clear
php artisan optimize:clear
```

Afterward, hard refresh the browser (Cmd+Shift+R on macOS) to discard cached CSS. Check Dashboard, Profile, Order History, Rewards, Refer a Friend, Returns, Downloads, Addresses, Payment Methods and Artwork Approvals on desktop and mobile.

## Cloud QR diagnosis
The uploaded application source **does not contain** a QR-code generator, QR-specific route, QR view/widget or recognized QR composer dependency. That means a specific server or code defect cannot be assigned to QR generation from this archive. The QR on the cloud may be generated by another deployed version, a third-party system, a static asset, or client-side code not in this package.

On the cloud, from the actual deployed NextPlay project root, these read-only checks are useful:

```bash
php artisan route:list | grep -i qr || true
grep -RniE 'QrCode|qrcode|qr[_-]?code|endroid|baconqr' app routes resources config 2>/dev/null | head -40
php -m | grep -Ei 'gd|imagick' || true
php artisan about
ls -ld public/storage storage/app/public 2>/dev/null
```

Find the failing QR request in the browser Network tab. Inspect its HTTP status (404: wrong/missing path or route; 403: permissions/auth; 500: server exception; blocked mixed content: HTTP asset on HTTPS page). For a *public* file-based QR (not a private artwork/payment asset), also check whether `public/storage` points to the intended storage directory. Only if your actual QR implementation stores **public** QR files in Laravel's public disk, run `php artisan storage:link` when the link is missing. Do not expose private order files or create a public symlink to private storage.

Read `storage/logs/laravel.log` around the failure time and look for QR-specific exceptions; never share API secrets, customer data, or complete `.env` files. Confirm your CDN/proxy is not caching or blocking the QR URL. If QR uses an external API, verify the provider URL and TLS/network access from the cloud separately.

To identify the exact failing behavior, capture **which page shows the QR**, the browser console/network error and its response code, and any sanitized Laravel exception. Without those, asserting that the code or cloud environment is at fault would be speculation.
